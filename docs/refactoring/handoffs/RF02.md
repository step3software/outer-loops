## Verified prerequisites

The merged RF01 suite supplies synthetic current and two distinct legacy save fixtures (`maxTown`, `version75`, old action aliases, `storyReqs`), current `ILSV01` imports, three challenge mode entry/exit/reload flows, old prestige grant/reset/backup and a reproducible invalid-JSON import that **overwrites the active slot before parse failure**. RF01 **does not** supply an authentic old-save corpus, comprehensive quota/recovery tests or exhaustive predictor parity.

**Source risks found during preparation:**
- `processSave` currently writes before parsing, then mutates queues/loads/pauses/restarts.
- `load/doLoad` mutate state; older embedded `challenge` migrations can **save and reload** mid-load.
- `storeSaveJson` catches and warns for some quota failures without propagating failure.
- `beginChallenge`, `exitChallenge` and `prestigeConfirmation` use distinct save slots, reloads and a valuable `prestigeBackup`.
- `GoogleCloud.importFile` calls shared `processSave`; OAuth/Drive code itself is **out of scope**.

## Scoped implementation sequence — use a fresh branch from current `dmchurch`

1. **Red tests first:** extend the merged RF01 fixtures and disposable Chrome profile to exercise P09–P22. Capture exact original bytes of `idleLoops1` / `idleLoopsChallenge` / `prestigeBackup` / import recovery keys on rejection. **Replace** the RF01 R01 "known unsafe" warning with a failing safety assertion before the fix; never make the bug into a required behavior.
2. **Pure preflight:** decode bounded `ILSV01` and recognized legacy Base64/LZW, parse/validate structure and derive legacy migration candidates **without** changing live globals, DOM, worker snapshots, localStorage or calling `save()`/`location.reload`.
3. **Recoverable commit:** choose a tested backup key/retention/recovery policy **distinct from `prestigeBackup`**; abort on backup/quota failure; protect the unrelated slot; ensure errors while loading or legacy challenge migration roll back the prior slot and live session. No claim that multi-key storage writes are atomic.
4. **UI/integration:** use one safe import boundary for pasted text, file imports and cloud-loaded payloads; maintain original `processSave` caller behavior unless all callers are intentionally updated. Keep explicit confirmed deletion distinct from invalid/nonempty text; report errors without showing raw private save contents.
5. **Proof/docs:** pass [P01–P22](../rf02-test-matrix.md) and [A1–A8](../RF02-persistence-safety.md), all previously merged RF01/Chrome/Worker checks, and update [persistence contract](../../audit/persistence-contract.md), [state guide](../../state-and-saving.md), [findings](../../audit/findings.md) and an ADR if persistence semantics change. Include a tested revert/recovery path.

**Boundaries:** No action/balance changes, challenge-rule rewrite (RF04), numeric/boolean resource rewrite (RF03), Google OAuth/Drive changes, new externally incompatible save envelope or new Real World outer-state schema. Use only synthetic private-data-free fixtures and a disposable browser origin.
